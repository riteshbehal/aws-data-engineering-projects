# Event-Driven Trip Processing Pipeline using AWS Kinesis, Lambda, DynamoDB, and Glue

## Overview

This project demonstrates how to build a real-time event-driven data processing pipeline on AWS for a ride-hailing platform.

The solution uses Amazon Kinesis to stream trip events, AWS Lambda to process those events, Amazon DynamoDB to maintain trip state, AWS Glue for data aggregation, and Amazon S3 for storing analytical outputs.

Unlike traditional batch pipelines, processing happens automatically as events occur, enabling near real-time analytics and operational visibility.

---

## Business Scenario

Imagine a ride-hailing company similar to Uber, Lyft, or Ola.

Every trip generates two events:

- A trip start event when a ride begins
- A trip end event when the ride completes

The business wants to process these events immediately so that trip information remains up to date and analytics can be generated continuously.

The solution should:

1. Capture trip start events in real time.
2. Update trip records when trips end.
3. Maintain the latest trip state.
4. Generate aggregated metrics automatically.
5. Store analytical outputs for reporting.
6. Operate without manual intervention.

---

## Solution Architecture

### Step 1: Stream Trip Events

Trip start and trip end records are streamed into Amazon Kinesis.

### Step 2: Process Trip Start Events

A Lambda function consumes trip start events and creates trip records in DynamoDB.

### Step 3: Process Trip End Events

A second Lambda function consumes trip end events and updates the corresponding trip records with completion details.

### Step 4: Trigger Aggregation

After successful trip completion updates, an AWS Glue job is triggered automatically.

### Step 5: Calculate Metrics

The Glue job reads completed trip records from DynamoDB and generates aggregated trip statistics.

### Step 6: Store Results

The aggregated results are written to Amazon S3 for reporting and analytics.

## Input Datasets

### trip_start.csv

Contains trip initiation records including:

* Trip ID
* Pickup information
* Passenger details
* Estimated fare
* trip_end.csv

### trip_end.csv

Contains trip completion records including:

* Trip ID
* Drop-off information
* Fare amount
* Tip amount
* Total amount

## Key Services Used

### Amazon Kinesis

Streams trip events in real time and acts as the ingestion layer for the pipeline.

### AWS Lambda

Processes incoming trip events automatically without requiring server management.

### Amazon DynamoDB

Stores trip information and maintains the latest state of every trip.

### AWS Glue

Aggregates completed trip records and generates analytical metrics.

### Amazon S3

Stores aggregated output generated by the Glue job.

### Amazon CloudWatch

Provides logging and monitoring for Lambda functions and Glue jobs.

### IAM

Controls permissions and secure communication between AWS services.
