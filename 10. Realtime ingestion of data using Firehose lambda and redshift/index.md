# Real-Time Data Ingestion into Redshift using Kinesis Firehose, Lambda, and Kinesis Data Streams

## Overview

This project demonstrates how to build a real-time data ingestion pipeline on AWS for clickstream analytics.

The solution uses Amazon Kinesis Data Streams as the streaming source, Amazon Kinesis Firehose as the data delivery service, AWS Lambda for real-time data enrichment, Amazon S3 as intermediate storage, and Amazon Redshift Serverless as the analytics data warehouse.

The objective is to capture streaming clickstream events in real time, enrich the incoming records, and load them directly into Redshift for reporting and analytics.

---

## Business Scenario

Imagine an organization that continuously collects clickstream events from its website and mobile applications.

The incoming data contains information such as:

* User activity
* Session details
* IP addresses
* Browser information
* Traffic sources
* Event types
* Geographic information

The analytics team wants near real-time visibility into customer behavior and website activity.

The solution should provide:

1. Real-time ingestion of clickstream events.
2. Automated data enrichment before loading.
3. Continuous delivery into a data warehouse.
4. Real-time reporting capabilities.
5. Fully managed and scalable architecture.

---

## Solution Architecture

### Step 1: Stream Clickstream Data into Kinesis

Website and application events are continuously written into an Amazon Kinesis Data Stream.

### Step 2: Deliver Streaming Data using Kinesis Firehose

Amazon Kinesis Firehose consumes records directly from the Kinesis Data Stream.

The Firehose delivery stream:

* Reads streaming events
* Buffers incoming records
* Invokes Lambda transformations
* Delivers processed data to Redshift

### Step 3: Enrich Records using AWS Lambda

AWS Lambda performs lightweight transformations and data enrichment before records are loaded.

The enrichment process:

* Cleans incoming records
* Applies schema validation
* Derives additional attributes
* Standardizes event data

### Step 4: Store Intermediate Data in Amazon S3

Amazon S3 acts as the underlying storage layer used by Firehose during data delivery operations.

### Step 5: Load Data into Amazon Redshift

Amazon Redshift Serverless receives the enriched clickstream data for analytics and reporting.

### Step 6: Query for Real-Time Reporting

Analysts can query Redshift tables using SQL to generate near real-time business insights.

## Key Services Used

### Amazon Kinesis Data Streams

Captures and streams clickstream events in real time.

### Amazon Kinesis Firehose

Provides fully managed delivery of streaming data into Redshift.

### AWS Lambda

Performs lightweight transformations and data enrichment before ingestion.

### Amazon S3

Acts as intermediate storage during Firehose delivery operations.

### Amazon Redshift Serverless

Stores enriched clickstream data for analytical workloads.

### IAM

Manages permissions between AWS services.

### Amazon CloudWatch

Monitors Firehose delivery streams, Lambda executions, and pipeline health.

## Data Enrichment Performed

### Mobile Device Classification

Adds mobile device indicators for user activity analysis.

### Traffic Source Categorization

Groups traffic sources into business-friendly reporting categories.

### Data Validation

Ensures incoming records conform to the expected schema before loading.

## Project Result

By the end of the project, clickstream events are captured in real time using Amazon Kinesis Data Streams, enriched through AWS Lambda, delivered by Kinesis Firehose, temporarily staged in Amazon S3, and loaded into Amazon Redshift Serverless for analytics. The solution provides a scalable and fully managed architecture for real-time data ingestion and reporting without requiring complex Spark Streaming jobs.
